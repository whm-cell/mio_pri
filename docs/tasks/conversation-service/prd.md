# 后端对话服务 PRD

状态：原 D1/D2 本地结果及已披露限制已接受，见[成果入口](complete/report.md)。当前沿原 W1/W2 核验动态目录、模型扩展和默认文本闭环；用户已明确 Claude/Messages 进一步适配及真实验收为后续条件项，不阻塞本期，保留现有实现、测试与历史未验事实。W1/W2 新候选分别验证和接受，不重开 D1/D2，不自动继承旧证据。必要隔离文本验证沿本人 Key 及既有授权，精确测试 ID 为 deepseek-v4.1-flash；不提交发布、不迁移共享/生产库、不扩大媒体授权。

## 目标与边界

用户已确认：本仓库是后端 service，逐步积累后续业务可复用的公共能力；近期优先接入 DSH 已有的多轮对话和 Agent 底层，复用已接受的认证与 PostgreSQL。对话以最小的“用户 → 对话”归属成立，不要求先有项目 CRUD。

本期规划覆盖登录后的对话创建、列表、历史、发送，多轮上下文、事件流、取消，以及明确的持久化、断连重连和进程重启语义。DSH 的 Agent/Session 是执行与内容基础，Mio 补足可信身份、归属和对外服务契约，不维护第二套 Agent 循环。

当前不建设项目、剧本、素材、生成等漫剧业务，不建设正式 UI、团队/多租户、通用工作流、队列/缓存平台或默认多智能体编排。既有 Redis 继续服务已接受的认证限流，本期不因有 Redis 就将其用于对话队列或内容存储。模型工具的生产授权仍为全部拒绝。

必要的简易调试前端可在以后另建同级独立项目，只消费公开接口；它不进入本仓库，也不成为服务构建、检查或接受的硬依赖。本次不创建该项目，本期验收路线采用 API 客户端和隔离测试，具体行为仍需实际观察。

## 本期能力与候选服务契约

[万联 PRD](../onelink-integration/prd.md)维护 W1 动态目录和 W2 适配/准入方案：当前用户 Key 的动态集合为唯一成员权威，旧 92 条仅作迁移参考，不参与生产名单。本轮核验模型增长后的已有协议复用、未知适配拒绝及默认文本闭环；参数差异/新协议依据实际需要局部扩展，不重建账号、会话或消息真相。D1/D2 已接受，本轮核对受影响回归，保留其结果和证据，见[对话交付衔接](#对话交付衔接)。

下表保留原最小服务轮廓；既有及本轮动态目录增量行为以[现行 HTTP 契约](../../apis/conversations.md)为准，需求见下节。W1/W2 已确定受影响字段、错误与持久版本；收尾时核对消费者与规范一致，不能以规范存在替代行为证据。

| 能力      | 候选入口与行为                                                                                        | 必要边界                                                                       |
| --------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 创建/列表 | `POST /api/v1/conversations`、`GET /api/v1/conversations`；服务生成稳定 ID，列表按当前用户且有界分页  | 不接受客户端自授 owner；未持久创建失败不得返回已持久成功。                     |
| 历史      | `GET /api/v1/conversations/:id/history`；投影用户可见的已记录消息、状态和中断标记                     | 每次校验当前身份与归属；不直接返回原始 Session 日志，不以全量读代替有界返回。  |
| 发送/多轮 | `POST /api/v1/conversations/:id/messages`；普通用户输入走 `followup`，恢复同一 DSH Session 延续上下文 | `steer` 是内核能力，不默认新增公共控制入口；并发、幂等及回执层级按 OPEN 决定。 |
| 事件流    | `GET /api/v1/conversations/:id/events`；优先评估 SSE，投影当前输出、运行状态与终态                    | 流与历史的重连边界明确；订阅不授予模型工具能力，不承诺每个瞬态 chunk 可重放。  |
| 取消      | `POST /api/v1/conversations/:id/cancel`；调用公开取消能力，并返回可查询的处理结果                     | 仅所有者可取消；取消请求、实际终止和已持久终态区分，不声称撤销已经发生的动作。 |

应用服务统一接收可信主体并检查归属，HTTP 只适配协议；DSH 适配集中在真实需要的装配/适配边界。候选持久化分工是 PostgreSQL 保存对话归属与服务接收信息，DSH 原生持久化保存会话内容，避免自建第二份消息真相。两者没有天然原子事务，创建/发送顺序、局部失败和重复请求恢复必须按 O2/O3 确定后再实现；不借用认证内部表或池，也不把开发 `.work` 当作产品数据。

候选运行方式是继续使用独立 Mio Profile，在同一进程装配官方 Agent、驱动、Session、JSONL 持久化及实际所需模型适配。既有 DSH Web 不是运行依赖，服务通过公开包接口接入，不通过抓取 Web 页面或依赖其端口执行。`sdk-minimal` 包含 Shell 等能力，不能直接照搬为生产 Profile。新增包按固定版本、真实消费者和最小装配选择，不为目录形状加载默认大 Bundle。

这些新增机制的依据是：跨用户访问会泄露内容，需要归属检查；断网重试可能重复接收，需要明确请求身份与回执；重启可能丢失未结算尾部，需要持久屏障和中断语义。优先复用 DSH 日志/恢复及现有身份解析，代价是增加一个服务适配与必要持久元数据；没有证据支持再加入通用状态机、队列、缓存、自动重试或多智能体协调层。

### 动态目录对对话的增量要求

四表、刷新和迁移由[万联方案](../onelink-integration/prd.md#42-用户配置模型选择和凭据生命周期)统一维护，对话侧必须贯穿以下接收路径，不能只更新供应商列表：

1. **选择与偏好**：创建时的显式 modelRef/业务默认、用户偏好校验、旧无绑定会话的一次绑定，都核对本人当前凭据动态成员及适配用途/启用状态。未知分类不强塞 chat，能力未知不猜协议或兜底 OpenAI；待适配模型立即可见，但没有已实现适配不能调用。默认失效明确返回原因，不自动选择相近型号或测试默认。
2. **身份与旧引用**：使用配置内精确原始 ID 的稳定模型身份，大小写保留，分类/协议/适配变化不另建模型。保留旧含分类 modelRef 的兼容解析和历史/回执原值；当前目录缺失的历史引用标不可用，不删除偏好，不从旧 92 条或失败发现生成可用成员。迁移中保持既有请求摘要与去重兼容。
3. **每次新输入**：先鉴权、归属及 requestId/内容去重；已有回执优先返回，不先检查当前目录/默认/凭据，也不重发。fresh 输入才在同一一致读取中核对并冻结 providerConfigId、稳定模型/原始 ID、credentialVersion、catalogVersion、适配声明版本与 operation/profile。临时刷新失败允许同凭据最近成功的 stale 快照中已适配项；从未成功、成功空目录、认证失败、换 Key 尚未重新成功、模型移除均按各自原因阻止新的调用。
4. **会话与恢复**：已绑定会话不随默认、目录或分类变化换模型，每次 fresh 发送重新检查当前资格；移除/失效后历史和旧回执可读，新输入拒绝且不产生收费接收。在途请求一直消费接收时冻结的模型和版本，刷新不替换它；重启保留失效事实与 unknown/终态，不从历史绑定或静态名单恢复新请求资格、不重放收费请求。
5. **DSH 消费者**：Mio 持有用户目录及请求级准入，继续复用固定公开 DSH/Pi 协议、Agent/Session/持久化。改造服务层选择/解析及 src/dsh/onelink.ts 的 metadata/listModels/resolveModel/prepareCall 和全部间接静态依赖；metadata/prepare/dispatch 属于同一可信快照。全局 listModels 没有 owner，不能合并用户目录、读取任意用户凭据或成为绕过准入的入口；无可信绑定不能取得用户模型资格。上游源码保持独立。

这些变更在新版 W1/W2 实施时同步供应商/对话 HTTP、业务规范及 DSH/万联集成正文，再由原 D2 回归消费。仅更新本 PRD 不声称现行规范或模型运行资格已经改变。

## OPEN 决定及最小解决动作

| ----------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| O1 模型与成本     | 动态目录唯一成员、稳定身份、用途默认、同请求版本冻结与 BYOK 无兜底保持；本期真实文本为当前目录精确 deepseek-v4.1-flash | W1/W2 核验扩展及正式 API 多轮/SSE/历史/取消/恢复；Messages 进一步适配和真实验证为后续项，不阻塞本期，旧目录外 Claude 仅历史观察 |

| O4 断连/取消/重启 | 用户确认断网不取消，重连补历史/原回执，重启不重发；取消绑定实际受理请求，真实终态另查                                  | 正常停止和 SIGKILL 分别观察；旧 interrupted/unknown 可见，未结算 chunk 不承诺重放，不宣称任意崩溃零丢失                         |

| O6 数据范围       | 用户确认仅本地测试账号/内容，隔离数据可清理；不开放删除/共享/导出                                                      | 真实用户保留/删除和上线容量另定，未授权真实用户内容或无限保留                                                                   |

## 本期开发单元与 C0/C1 安排

规划、开发与接受分别判断，沿[仓库生命周期](../../coordination.md#当前任务的生命周期)。下面保留原 D1/D2 的范围、C0/C1 安排和验收依据；两项已真实接受，不是本轮待执行计划。本轮实施对象为万联 PRD 的原 W1/W2，仅核对其变更的受影响回归，不重新准备或改写 D1/D2 接受。

### D1：受控 DSH 内核装配与持久化边界

- **结果与范围**：在独立测试环境通过正式公开包装配 Agent/Session/驱动和原生持久化，证明普通多轮、恢复、取消及事件结算边界可供 Mio 消费，形成最小可复用接入及验证入口。内核判据保留确定性模拟模型和无副作用夹具；真实适配链路的补充观察在 W2/D2 已授权批次取得，不为 D1 新增独立收费或全模型实测前置。不承担公共对话 API、真实用户内容、项目或工具授权。
- **C0 决定/授权/依赖**：当前实施授权已取得，固定公开包和独立临时持久根可用，夹具无外部副作用。按公开导出及已有 Profile 选择最小装配，有界 src/dsh 适配与合法/违规样例一并维护；行为证据属于 C1，O1 不阻塞模拟验证。
- **C1 实施与依赖顺序**：先装载官方服务并创建/恢复明确的 `dshSessionId`，再经 `followup` 连续两轮；在 `setup` 中注册作用域观察，区分 live stream、已结算内容和 flush；最后覆盖取消、卸载、重启和损坏/中断尾部。优先保持现有单一 DSH 入口；若真实职责要求适配模块，连同护栏和编译覆盖一起落实，不导入上游内部源码。
- **验收与接受**：同一候选实际执行模拟模型→官方 loop→Session→真实隔离持久化，证明第二轮使用已记录上下文、重启后可恢复已持久前缀；保存正常关闭和强制中断的差别、未落盘/未知结果及资源释放观察。验证生产守卫下工具函数不执行，测试夹具不泄入 Profile。相关检查、质量/规范审阅与真实接受齐备才接受该内核切片；它不等于真实模型或公共服务验收。

### D2：用户归属的对话 API 与完整运行验收
