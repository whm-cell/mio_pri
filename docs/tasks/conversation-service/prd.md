# 后端对话服务 PRD

状态：用户已在后续对话明确授权实施 D1/D2，当前进入本地开发与验收；尚未接受。最初文档编制阶段仅授权 PRD 和安排，其归档记录保留原事实；当前实施记录独立建立，不倒写旧授权。范围仍不包含前端项目、上线或真实模型费用。

## 目标与边界

用户已确认：本仓库是后端 service，逐步积累后续业务可复用的公共能力；近期优先接入 DSH 已有的多轮对话和 Agent 底层，复用已接受的认证与 PostgreSQL。对话以最小的“用户 → 对话”归属成立，不要求先有项目 CRUD。

本期规划覆盖登录后的对话创建、列表、历史、发送，多轮上下文、事件流、取消，以及明确的持久化、断连重连和进程重启语义。DSH 的 Agent/Session 是执行与内容基础，Mio 补足可信身份、归属和对外服务契约，不维护第二套 Agent 循环。

当前不建设项目、剧本、素材、生成等漫剧业务，不建设正式 UI、团队/多租户、通用工作流、队列/缓存平台或默认多智能体编排。既有 Redis 继续服务已接受的认证限流，本期不因有 Redis 就将其用于对话队列或内容存储。模型工具的生产授权仍为全部拒绝。

必要的简易调试前端可在以后另建同级独立项目，只消费公开接口；它不进入本仓库，也不成为服务构建、检查或接受的硬依赖。本次不创建该项目，本期验收路线采用 API 客户端和隔离测试，具体行为仍需实际观察。

## 本期能力与候选服务契约

以下是 AI 提出的最小服务轮廓，用于评审和后续实施，不是现行 API。身份、归属、错误、副作用和验收须在相关 C0 收口，实际落地时才将已采用契约加入[API 领域导航](../../apis/index.md)。路径命名、字段名等可逆细节由实施者集中确定，不逐项设置人类审批。

| 能力      | 候选入口与行为                                                                                        | 必要边界                                                                       |
| --------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 创建/列表 | `POST /api/v1/conversations`、`GET /api/v1/conversations`；服务生成稳定 ID，列表按当前用户且有界分页  | 不接受客户端自授 owner；未持久创建失败不得返回已持久成功。                     |
| 历史      | `GET /api/v1/conversations/:id/history`；投影用户可见的已记录消息、状态和中断标记                     | 每次校验当前身份与归属；不直接返回原始 Session 日志，不以全量读代替有界返回。  |
| 发送/多轮 | `POST /api/v1/conversations/:id/messages`；普通用户输入走 `followup`，恢复同一 DSH Session 延续上下文 | `steer` 是内核能力，不默认新增公共控制入口；并发、幂等及回执层级按 OPEN 决定。 |
| 事件流    | `GET /api/v1/conversations/:id/events`；优先评估 SSE，投影当前输出、运行状态与终态                    | 流与历史的重连边界明确；订阅不授予模型工具能力，不承诺每个瞬态 chunk 可重放。  |
| 取消      | `POST /api/v1/conversations/:id/cancel`；调用公开取消能力，并返回可查询的处理结果                     | 仅所有者可取消；取消请求、实际终止和已持久终态区分，不声称撤销已经发生的动作。 |

应用服务统一接收可信主体并检查归属，HTTP 只适配协议；DSH 适配集中在真实需要的装配/适配边界。候选持久化分工是 PostgreSQL 保存对话归属与服务接收信息，DSH 原生持久化保存会话内容，避免自建第二份消息真相。两者没有天然原子事务，创建/发送顺序、局部失败和重复请求恢复必须按 O2/O3 确定后再实现；不借用认证内部表或池，也不把开发 `.work` 当作产品数据。

候选运行方式是继续使用独立 Mio Profile，在同一进程装配官方 Agent、驱动、Session、JSONL 持久化及实际所需模型适配。既有 DSH Web 不是运行依赖，服务通过公开包接口接入，不通过抓取 Web 页面或依赖其端口执行。`sdk-minimal` 包含 Shell 等能力，不能直接照搬为生产 Profile。新增包按固定版本、真实消费者和最小装配选择，不为目录形状加载默认大 Bundle。

这些新增机制的依据是：跨用户访问会泄露内容，需要归属检查；断网重试可能重复接收，需要明确请求身份与回执；重启可能丢失未结算尾部，需要持久屏障和中断语义。优先复用 DSH 日志/恢复及现有身份解析，代价是增加一个服务适配与必要持久元数据；没有证据支持再加入通用状态机、队列、缓存、自动重试或多智能体协调层。

## OPEN 决定及最小解决动作

用户已经确认 O2/O4/O5/O6/O7 的本地语义；O3 是 PRD 方向和实施授权下采用的技术分工。固定值、字段及协议在[本地对话规范](../../conversations.md)和[HTTP 契约](../../apis/conversations.md)唯一维护，不把技术采用改写成用户逐项原话。实际证据属于 C1；未决仅暂停依赖部分。

| 项                | 当前决定/边界                                                                                                                           | 剩余动作与阻塞范围                                                                                               |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| O1 模型与成本     | 服务端一个 provider/model，不接受客户端模型或密钥；正式 Profile 已提供固定版 DeepSeek 官方 API-key 适配的显式配置入口，当前没有真实配置 | 确认实际模型、密钥位置及有界调用预算后实测；只阻塞真实供应商调用/验收，不阻塞模拟、真实存储、HTTP 与恢复         |
| O2 并发/去重      | 用户确认同对话忙时拒绝、不同对话独立；同 request ID 同内容复用原回执、异内容冲突。ID 随本地会话元数据保留                               | 按实际入模计数、真实 PG 提交/ACK 故障核对，不宣称模型或外部动作 exactly once                                     |
| O3 持久化/回执    | 技术采用 PG 归属/接收元数据 + DSH 原生日志，先映射/接收再原生屏障/结算；跨存储失败 unknown，不自动重发，不双写消息真相                  | 核对创建局部失败、接收与结算 ACK、flush 故障、原身份查询和实例重启；对账失败停止后续操作，操作者停止旧实例后恢复 |
| O4 断连/取消/重启 | 用户确认断网不取消，重连补历史/原回执，重启不重发；取消绑定实际受理请求，真实终态另查                                                   | 正常停止和 SIGKILL 分别观察；旧 interrupted/unknown 可见，未结算 chunk 不承诺重放，不宣称任意崩溃零丢失          |
| O5 登录失效       | 每次操作重新验证身份/归属；长流每秒复核，失效拒绝新操作并关流，已受理轮次允许完成                                                       | 真实账号撤销/过期、长流和在途结算分别核对；登录 Session 不等于 DSH Session                                       |
| O6 数据范围       | 用户确认仅本地测试账号/内容，隔离数据可清理；不开放删除/共享/导出                                                                       | 真实用户保留/删除和上线容量另定，未授权真实用户内容或无限保留                                                    |
| O7 公开投影       | 用户确认仅可见文本/状态/脱敏错误；输出服务标识和必要 cursor，不透传系统/推理/工具/凭据/路径/trace                                       | 持久历史与瞬态流分别白名单投影，含敏感受控事件做反例；基线/订阅交接、清理及缓冲边界纳入 HTTP 验收                |

生产工具仍全部拒绝。D1 可在独立测试实例使用无文件、网络或外部副作用的验证夹具观察真实工具执行链；不得带入生产 Profile。当前守卫是单调拒绝，后注册 allow 不能将其覆盖；若未来业务要求工具，须另行明确身份、输入、资源归属与副作用，不属于本 PRD 的默认授权。

## 本期开发单元与 C0/C1 安排

规划可交回、开发就绪和实现已接受分别判断，沿[仓库生命周期](../../coordination.md#当前任务的生命周期)。下面是两个已获本地实施授权的开发结果；真实现场和证据在各自执行记录维护，不与先前文档任务的阶段混淆。

### D1：受控 DSH 内核装配与持久化边界

- **结果与范围**：在独立测试环境通过正式公开包装配 Agent/Session/驱动和原生持久化，证明普通多轮、恢复、取消及事件结算边界可供 Mio 消费，形成最小可复用接入及验证入口。先使用确定性模拟模型和无副作用夹具；不开放公共对话 API，不接收真实用户内容，不调用付费供应商，不加入项目或工具授权。
- **C0 决定/授权/依赖**：当前实施授权已取得，固定公开包和独立临时持久根可用，夹具无外部副作用。按公开导出及已有 Profile 选择最小装配，有界 src/dsh 适配与合法/违规样例一并维护；行为证据属于 C1，O1 不阻塞模拟验证。
- **C1 实施与依赖顺序**：先装载官方服务并创建/恢复明确的 `dshSessionId`，再经 `followup` 连续两轮；在 `setup` 中注册作用域观察，区分 live stream、已结算内容和 flush；最后覆盖取消、卸载、重启和损坏/中断尾部。优先保持现有单一 DSH 入口；若真实职责要求适配模块，连同护栏和编译覆盖一起落实，不导入上游内部源码。
- **验收与接受**：同一候选实际执行模拟模型→官方 loop→Session→真实隔离持久化，证明第二轮使用已记录上下文、重启后可恢复已持久前缀；保存正常关闭和强制中断的差别、未落盘/未知结果及资源释放观察。验证生产守卫下工具函数不执行，测试夹具不泄入 Profile。相关检查、质量/规范审阅与真实接受齐备才接受该内核切片；它不等于真实模型或公共服务验收。

### D2：用户归属的对话 API 与完整运行验收

- **结果与范围**：以当前可信身份实现创建/列表/历史/发送、流式订阅和取消，关联对话归属与 DSH Session，并交付同一结果必需的恢复、权限、实际流式及真实模型联调。复用认证与 PostgreSQL，按 O3 采用内容持久化分工。不包含正式 UI、项目 CRUD、素材生成、团队权限、任意模型选择或生产工具。
- **C0 决定/授权/依赖**：本地实施授权、O2/O4/O5/O6/O7 与 O3 技术分工已收口，消费当前已核实且可取得的 D1 接入；具体契约在[对话规范](../../conversations.md)和[HTTP](../../apis/conversations.md)。O1 实际供应商/预算未配置，只阻塞依赖它的真实调用与完整接受，其他实施继续；尚无真实模型原件是 C1 缺口，不倒置成模拟/存储/API 的实施前置。
- **C1 实施与依赖顺序**：先落实用户→对话归属、迁移/连接责任和稳定 ID；再实现接收回执与 DSH 调用、公开历史/事件投影和取消；把并发/重复、跨存储失败、身份过期/撤销、断线重连和进程恢复随同各路径实现测试。真实供应商联调在配置与费用授权后进行，使用最小输入和已定预算。必要 API/持久化/模型公共契约与导航在 verify 前形成，保持既有认证及 Redis 约束；不把未采用候选搬成现行规范。
- **验收与接受**：必须通过下节所有适用判据、完整 `pnpm check`、质量/规范和独立审阅；模拟、真实存储、真实 DSH、真实模型分别报告。恢复、权限和实际流式联调是 D2 的必需交付，不是可选尾项；只有匹配候选的原件和真实人类接受后才交付该服务结果。缺模型或环境就保留相应 pending，不从模拟通过推导真实联调或生产就绪。

D1 的内核接入可独立核验并被 D2 消费，故单列；D2 的恢复、权限和流式行为直接决定同一 API 的正确性，本期合并交付，不再机械拆出第三个“以后补测”的单元。实现中只有出现可独立核验的结果或不同依赖/写入责任，才调整拆分，公共计划仍维护在本页。

当前本地实施按 D1/D2 验收和真实接受条件推进。真实模型缺配置时单列 pending，不用模拟替代、不 complete 整项服务；部署与费用仍须实际授权。原文档编制阶段的停止条件只约束该历史文档任务，不撤销当前已明确取得的实施授权。
