# 验收标准与入口

当前插件与工程护栏的共同判据见 [底座规格](foundation.md#验收与限制)，接口契约见 [API 约定](api.md)。静态检查、插件装载、业务观察、人工接受与远端门禁分别判断，不能相互替代。

公共开发成果从[任务静态入口](tasks/index.md)或 `pnpm work documents --select /results` 查找，每份注册 PRD 独立发现已接受成果，再按需要读取具体结果与必要证据。每项绑定自己的受验版本，历史通过不能代表当前改动，成果数量不表示 PRD 整体完成。prepare 只生成私有草稿；真实接受后 complete 按稳定 key 仅更新所属 PRD 的 records/report，保留其他结果。维护、检查和演练验证后按需 archive，不发布公共 complete，个人过程留在本人 `.work`。跨人评审按既有共享渠道取得必要材料，不要求访问作者私人目录。

执行与交付方法见 [协调协议](coordination.md#任务交付与重开) 和 [交付命令](work-records.md#交付命令)。根入口不要求读取历史验收正文。

## 无个人 Skills 的任务路线验证

维护拆解、生命周期或动作入口时，除现有 CLI 回归外，用隔离仓库验证 Agent 行为。环境只提供仓库、项目依赖和原始 PRD／用户目标，不提供个人 Skills、历史对话、已填好的任务 JSON 或对应场景的现成计划答案；运行者需具备读写文件和执行命令的能力。记录实际可见上下文与操作，无法隔离时标明该项未验证，不能以未主动调用 Skill 冒充无 Skill 验证。

- 从仓库入口观察 Agent 是否按[规划交付要求](coordination.md#规划交付要求)形成公共执行安排，并在文档任务验收中核对开发单元的具体安排；规划可交回、开发已就绪、实现已接受分别判断。相关关键未知保留影响范围和解决动作，不使无依赖工作全部停工。
- 从实际入口完成一项有界修改，核对生成文件、验收原件、候选与状态；仅有任务字段或报告文本不算行为通过。
- 涉及写入入口或命令生命周期时，观察实际工具调用：脚本写文档（含私有审阅原件）、formatter 和带重定向的命令应把完整副作用放进 work exec；取证阶段的原件准备按[验证与接受](coordination.md#验证与接受)核对实际入口。同任务长检查未结束时，竞争登记应在启动前被拒绝，读取和其他任务仍可推进。补真实取消／后代未结束与恢复场景，核对标记、原件和退出结果，不用文案匹配代替。
- 涉及人工原件时，核对实际候选、验收项和每份原件的写入归属。注入旧观察登记到新候选、重写已登记路径和链接别名，确认登记拒绝且不增加通过；新路径的真实当前观察可登记。把原件当作脚本／配置／预期结果输入时须回实施；多人可并行准备各自观察，任务状态与登记由同一写入者收口。
- 在任务尚未交回时中断当前 Agent（可尚无原件，也可已有部分通过或失败），用新的无历史上下文继续同一仓库；应找到原任务而非重复建档，核对现场后沿下一动作推进。后续明确实施指令按新授权处理，不能永久沿用早先的仅文档限制，也不能继承旧候选的通过。
- 涉及记录定位或推进时，核对真实章节、更正后的同一任务身份和当前 nextAction；完成修改、取证及归档后不得仍指向已消费动作。注入同阶段旧 revision 更新，确认 run/exec 不启动，读取后仍须合法 update 对账，契约更正后能继续 sync；另验交付中断优先恢复，不制造双重阻塞。不能只把字段问题写进审阅原件而不修记录。
- 缺证、旧候选或尚未接受时不得标记释放；拒绝和接受分支可由隔离 CLI 用例验证，不伪造真实项目的接受。公共产物和个人过程分别保持正确归属。
- 涉及自动验收时，验收目标与方法明确但缺完整命令应允许授权实施；正式取证及交付仍拒绝，返回实施可补齐脚本，实际漂移不能借阶段转换放行。用实际完整命令与局部命令对照：完整失败后补测成功、只有补测、完整成功后补测失败再成功、原件缺失或损坏均不得误绿；新完整通过可恢复，失败原件保留。变换验收 ID 不应改变判断；prepare／complete 同样须满足该判据。
- 涉及建档声明时，开发目标不能静默遗漏 result，维护显式无开发成果且不发布 complete；误声明在接受前可纠正，接受后不能清除绑定。阶段、nextAction 或仅 HEAD 变化不应要求重复同候选检查；真正改变验收命令、实现输入或观察环境时仍须核对并补当前证据。

围绕实际改动选择反例和正常变体：删除关键规划内容、混用文档与开发阶段时，审阅应指出具体缺口并保持未通过；更换业务或任务编号不应改变适用判断；增加远期条件项不应强迫当前任务预建记录或整体停工，小修改不应增加无关阶段和审批。审阅内容与行为，不用匹配 C0/C1 字样的测试代替。

主张改进时，固定旧版和候选版，用相同输入、环境和判据在独立上下文对照；相关初始化处理保持一致。保留原始请求、实际动作、产物、失败与未覆盖项，分别报告工具回归、Agent 行为、真实业务及远端门禁的覆盖。结果相同只能说明该对照未观察到差异，单次样例不能证明普遍可靠或长期收益。

结合本次规则推演首次规划、决定变化和换人接续：权威定义应能定位，必要更新留在原有位置，已有有效证据按影响复用，不产生重复计划、无关阻塞或例行全仓审计。发现问题后修补并复验受影响场景；按新问题补验证，不要求每次普通任务重做整链实验。

资料整理不重验历史业务或补造原日志，已有接受和必要公开依据仍从所属 PRD 成果读取。历史未接受或没有公开成果不能推断未实现；整理不改变既有接受，也不能把公开摘要提升为完整私人原件。涉及登记或候选隔离时，对照合法无关 PRD 增长、相关登记／契约／显式成果变化和显式广 scope；涉及交付写入时同时核对新增与更新 key 的实际 journal 目标、缺件／损坏／孤儿拒绝及旧请求恢复保护。运行验收使用独立 checkout/worktree，同 checkout 并发不作为隔离保证。
