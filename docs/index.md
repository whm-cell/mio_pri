## 增长与归属

`docs/` 是公共文档总目录；任务区统一在 `docs/tasks/`，新需求放 `docs/tasks/<稳定名称>/prd.md`，专属设计与未采纳提案同目录保存，从[任务总入口](tasks/index.md)经需求导航展开。其他页面按职责维护现行工程、模块、接口和操作规范。PRD 维护需求、范围、安排、验收和未决；设计维护方案理由，当前实现事实和接口只引用现行规范。新资料须可从入口发现，不从历史或已接受成果正文倒灌活动资料可达性。

来源身份与位置的唯一注册在 `harness.config.json` 的 `taskDocuments`，类别为 prd/design/proposal；identity 首次确定后保持不变，path 为当前位置，aliases 保留兼容入口。`pnpm work documents` 只读核对分类和问题，不自动迁移、重写引用或转移通过。旧页只保留短导航与历史锚点，未知、重复、越界、私有或符号链接资料拒绝。`docs/tasks/index.md` 固定导航到 `requirements.md` 与已接受成果，二者不构成第二份注册台账；complete/history 与活动任务正文分别校验。

需求的必需结果有证据和接受结论后结束该需求；不因结束把 PRD、设计或仍在使用的规范搬进 complete。全部新旧 PRD 的成果统一保存到 `docs/tasks/complete/<prd-id>/`，目录由稳定身份派生；旧接受元数据、成果与历史原件不因资料搬迁改写。历史快照只说明其受验版本，迁移会产生新候选；`.work` 保存个人过程、待接受草稿与原件。维护任务核对后按需 archive，不生成公共 complete。

同一事实只在上述权威位置维护，其他页面保留必要边界和短链接，不复制完整状态/运行流水。当前实现事实核对源码和现行契约，接受事实核对指定成果详情，两者不互相推导。日常不展开[历史依据](tasks/history/index.md)全文，需要追溯某项旧决定时才按精确链接读取。
