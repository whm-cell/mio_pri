# 插件服务底座

## 本阶段目标与来源

2026-11-05 项目决定：使用 TypeScript，通过 DeepSeek Harness（DSH）插件承接后续 AI 漫剧业务；插件服务独立部署，独立前端通过服务端口调用。当前只初始化基础护栏与最小可运行插件，不以旧 Python 行为替代业务需求。

本次授权包含工程与护栏文件、依赖安装、本地验证。完成边界是：可构建的插件产物通过官方 DSH Profile 装载，提供最小服务探针和受保护的能力查询；权限、结构和文档约束有真实正反例。没有推送、发布或生产操作。

本阶段不提供对话 API、流式事件、生成任务、数据库、前端、SaaS 多租户或模型调用。上次讨论的会话、重连、取消与业务资源授权是后续接口设计的验收维度；在这些入口实现前不标记为完成。

后续 [技术底座 PRD](prd-ai-drama-foundation.md) 已推进自助注册与用户会话切片，运行配置和验证入口见 [认证底座](auth.md)；上文保留最初 foundation 范围，不据此声称生成或项目业务已实现。

## 结构决定

| 对象           | 决定       | 理由和边界                                                                                 |
| -------------- | ---------- | ------------------------------------------------------------------------------------------ |
| 官方 DSH       | reuse      | 使用已发布 `0.2.2-rc.1`；参考源码提交 `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`，不改上游 |
| mio 插件包     | create     | 单个 ESM TS 包，使用 Profile/Bundle 装载；不维护第二套 Agent 循环                          |
| HTTP 处理      | create     | 产品接口只处理本阶段探针、鉴权与能力查询；DSH 路由适配集中于插件入口                       |
| 业务模块       | unresolved | 等具体业务需求后确定模块与数据归属，不创建空层                                             |
| 会话与生成任务 | unresolved | 后续明确身份、入队回执、事件、取消与恢复契约后再实现                                       |

运行时导入方向：插件入口 → HTTP 处理与契约；HTTP 处理 → 契约。只有插件入口可以导入 DSH/Cordis。测试可使用公开 DSH API 验证集成；运行时不得导入测试与开发脚本。跨包只使用发布的接口，不导入上游源码或其内部产物。

运行实例使用显式、独立的 `DSH_HOME`。当前 Profile 只装配 HTTP、工具注册和原生执行器等必要服务，没有模型适配器、文件工具、Shell、MCP 或动态插件管理工具；注册执行守卫拒绝全部工具。以后新增允许工具时必须同时定义输入、授权与副作用验收，不能仅增加工具名称。

## 验收与限制

- 核心：格式、类型、lint、护栏、测试、构建均成功；打包产物通过官方 `dsh --profile mio` 启动；受保护查询可用；正常停止后同一端口可再次绑定。
- 必要保障：缺少认证配置不可就绪；错误凭据、未知路径/方法与不允许的 Origin 被拒绝；真实工具函数在守卫下不执行；插件卸载撤销路由与守卫；结构/文档违规样例返回非零。
- 环境：Node 24（至少 24.9）、pnpm 固定版本、隔离的临时 DSH_HOME；没有生产数据、真实模型或收费供应商。源码导出可运行检查，Git 索引检查仅在 Git 仓库中有效。
- CI 文件只代表已接入配置；没有远端运行和分支保护证据时，不声称远端门禁已生效。

当前验收标准见 [验收入口](acceptance.md)，已接受开发成果通过 [PRD 成果索引](tasks/index.md) 定位；历史护栏维护与实验单独保留。个人执行状态、每轮结果及原件在各自 `.work` 维护，不在公共文档按日期追加。接口状态见 [API 约定](api.md)，日常命令见 [README](../README.md)。
