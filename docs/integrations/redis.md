# Redis 使用契约

## 适用范围与接入事实

项目采用官方 `@redis/client 6.2.1`，认证计数资源采用 Redis Open Source `8.2.11`，沿用 Node 24。版本在 [package.json](../../package.json) 与锁文件固定。服务端制品来自[官方发布目录](https://download.redis.io/releases/)，本轮固定 tar 的 SHA256 为 `fba14b77c4bdcb2d5418b6741fc0cdaac4b78bc73eab9b2e5f3c255d597f16fa`；编译输出中的 Git sha 可能来自外层工作区，不能用它认定 Redis 上游提交。

[公共运行入口](../../src/integrations/redis.ts)读取资源配置、建立一个复用的单节点连接、执行有界命令并释放资源。[插件入口](../../src/plugin.ts)创建、装配和释放，显式注入[认证消费者](../../src/auth/rate-limit.ts)。公共模块不包含认证路径、限额、业务键或 HTTP 错误政策，也不导出全功能驱动客户端。当前只提供实际消费所需的单键 EVAL、PTTL、DEL、停止和关闭能力；没有公共连接池、Cluster、Sentinel、缓存或队列框架。

认证后端选择、计数键、规则、503 和恢复等待由[认证底座](../auth.md#限流存储与恢复)维护。未来消费者引用本页并说明自己的数据、授权、TTL 与故障语义；不经认证内部取得 Redis，也不把当前认证资源策略当作其他业务默认。

## 必须遵守的约束

| 配置                  | 含义                                                                                                            |
| --------------------- | --------------------------------------------------------------------------------------------------------------- |
| `MIO_REDIS_URL`       | 服务端注入的单节点 URL；远程必须 `rediss://` 并校验证书；`redis://` 只允许 localhost、127.0.0.1 或 ::1 回环测试 |
| `MIO_REDIS_NAMESPACE` | 1–64 位小写字母、数字、下划线或连字符，标识环境/服务，正常重载保持稳定                                          |

仅提供 Redis 变量不会启用消费者。未使用资源时不解析或连接它；显式使用却缺项或启动失败时拒绝装载，不静默改用其他存储。URL、密码、连接错误堆栈不返回 HTTP、日志或公共报告；应用无权配置实例或清库。

当前资源禁用离线队列和自动重连，不自动重发命令。待答命令由固定驱动限制为 128；连接和消费者启动探测共享 5 秒单调时间预算。认证消费从进入 consume 起总预算 1 秒，关闭等待预算 1 秒；这些是本切片保护预算，不是容量或延迟 SLA，也不自动成为未来中间件默认。

公共失败分为：`rejected`（确定未执行，例如发送前队列满，或服务明确在脚本执行前拒绝的 OOM）、`unknown`（超时、断连、协议或脚本/状态异常）和已停止后的 `unavailable`。原始驱动错误不外泄。不能把任意服务端错误都归为已知拒写；错误类型、损坏数据和脚本内部错误均不能证明计数可信。未知结果销毁连接并拒绝后续操作；销毁不证明服务端已取消执行，消费者不得重放。

资源关闭先停止新操作，等已有有限在途操作结束，最多 1 秒后销毁连接；重复关闭不重新发送命令。创建失败、消费者探测失败、启动中卸载及正常卸载均释放已持有资源。AbortSignal 同时取消仍在 DNS 或 TLS 握手中的 socket，不能只依靠驱动已持有的连接标记。

认证计数的当前资源约束是独占单节点、`noeviction`、有限 `maxmemory`。原有故障夹具固定 128 MiB 并关闭 RDB/AOF，以显式验证丢失状态；[常驻开发/测试环境](../local-environments.md)各自使用独立容器和卷，固定 128 MiB、开启 AOF everysec、关闭 RDB。AOF 的异常故障窗口仍可能丢失近期写入，重启继续遵守认证排清和 65 秒等待，不推导自动恢复。生产容量须另定；命名空间或逻辑 DB 不隔离实例级淘汰与内存策略。运行账号只获自身 `mio:<namespace>:*` 前缀和 HELLO/认证、CLIENT SETINFO、EVAL、TIME、GET、SET、PTTL、DEL 等实际必需命令；常驻容器健康检查另允许 PING，不授予 CONFIG 或清库。资源版本、容量、淘汰/持久化及权限由操作者预检；应用不修改这些策略。

该资源不能与可淘汰缓存共用；后续业务要求重连、LRU、持久化或其他命令时，先核对资源相容性、现有消费者和公共约束，按实际影响调整。管理员不通知应用就删键或更改策略的情况没有自动完整性检测，独占资源和运维责任是成立前提。

## 使用经验与适用条件

固定客户端的 `commandOptions.timeout` 只覆盖尚未写入 socket 的命令；仅使用该选项不能约束已发出但不回包的操作。公共入口另设覆盖发送和等待的总期限，并在返回结果时复核单调时钟，避免事件循环阻塞后把迟到成功交给消费者。

6.2.1 的 `close()` 在等待待答前先把连接标为关闭，此后 `destroy()` 不能可靠销毁其尚未排清的 socket。本项目在调用者持有的有限在途集合上等待，届期直接在仍可销毁的连接上释放，不调用无界的 close。此取舍针对固定版本的实际生命周期行为，不依赖私有 `_ejectSocket` 或上游源码内部接口。升级客户端时须重新核对。

认证脚本使用 `#!lua`，让 Redis 在脚本执行前执行 OOM 检查；无 shebang 的兼容模式可能到脚本中的写操作才报错。单键原子执行不等于任意 Lua 都能回滚；其他消费者必须自行说明副作用与未知结果边界。[固定版客户端配置](https://github.com/redis/node-redis/blob/redis%406.2.1/docs/client-configuration.md)、[命令选项](https://github.com/redis/node-redis/blob/redis%406.2.1/docs/command-options.md)、[Redis 脚本](https://redis.io/docs/latest/develop/programmability/eval-intro/)

## 验证入口与变更影响

`pnpm test` 需要 PATH 中的 Redis 8.2.11，或通过 `MIO_TEST_REDIS_SERVER` 指向该二进制；缺失/版本不符明确失败，不跳过。安装示例见 [README](../../README.md#安装与检查)。

[Redis 夹具](../../tests/redis-server.ts)为每轮创建独占进程、随机回环端口和临时目录，结束后关闭并删除自己的资源，不接受任意共享 Redis URL 作为故障目标。[TCP 转发夹具](../../tests/redis-proxy.ts)将命令发往真实 Redis、扣留真实响应，用于核对已执行但结果丢失的计数及关闭。

[公共能力测试](../../tests/redis.test.ts)验证原子性、TTL、受控时间边界、ACL、队列、OOM、损坏状态、DNS/TLS 取消、启动总期限与有界关闭。[认证集成](../../tests/auth-redis.test.ts)组合真实 PostgreSQL、DSH HTTP 和独占打包 Profile，验证规则/响应/身份/存储、旧账号会话、失败无业务写入及受控切换回退。演练真实等待三次 65 秒，不使用假时间替代恢复等待。PostgreSQL 的隔离约束仍见[数据库契约](postgres.md#验证入口与变更影响)。

改变版本、命令、错误分类、连接/关闭、资源策略或新消费者时，回归实际受影响的入口与状态转移，并执行 `pnpm check`、源码边界正反例和质量/规范审查。CI 配置和本地验证分别报告；这些入口不证明生产容量、多实例、任意代理链或远端门禁已通过。
