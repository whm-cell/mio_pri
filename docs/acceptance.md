# 验收标准与入口

当前插件与工程护栏的共同判据见 [底座规格](foundation.md#验收与限制)，接口契约见 [API 约定](api.md)。静态检查、插件装载、业务观察、人工接受与远端门禁分别判断，不能相互替代。

公共开发成果从 [PRD 成果索引](tasks/index.md) 查找，每份 PRD 一个已接受成果入口，再按需要读取具体结果与必要证据。每项绑定自己的受验版本，历史通过不能代表当前改动，成果数量不表示 PRD 整体完成。prepare 只生成私有草稿；真实接受后 complete 按稳定 key 更新对应成果，保留其他结果。维护、检查和演练验证后按需 archive，不发布公共 complete，个人过程留在本人 `.work`。跨人评审按既有共享渠道取得必要材料，不要求访问作者私人目录。

执行与交付方法见 [协调协议](coordination.md#任务交付与重开) 和 [交付命令](work-records.md#交付命令)。根入口不要求读取历史验收正文。

## 无个人 Skills 的任务路线验证

维护拆解、生命周期或动作入口时，除现有 CLI 回归外，用隔离仓库验证 Agent 行为。环境只提供仓库、项目依赖和原始 PRD／用户目标，不提供个人 Skills、历史对话或已填好的任务 JSON；运行者需具备读写文件和执行命令的能力。

- 观察 Agent 是否按可验收结果形成公共执行安排，选择当前已授权且依赖就绪的任务；相关关键未知保持待定，不使无依赖工作全部停工。
- 从实际入口完成一项有界修改，核对生成文件、验收原件、候选与状态；仅有任务字段或报告文本不算行为通过。
- 在尚未取证或交付时停止当前 Agent，用新的无历史上下文继续同一仓库；应找到原任务而非重复建档，核对现场后沿下一动作推进。
- 缺证、旧候选或尚未接受时不得标记释放；拒绝和接受分支可由隔离 CLI 用例验证，不伪造真实项目的接受。公共产物和个人过程分别保持正确归属。

保留原始请求、运行环境、实际动作与结果，分别报告工具回归、Agent 行为、真实业务及远端门禁的覆盖。按新问题补验证，不要求每次普通任务重做整链实验；单次样例也不证明所有 Agent／宿主都能正确执行。

## 历史来源

原 v1 任务索引和十份交付包原字节保存在 [历史入口](tasks/history/index.md)，其中护栏维护和隔离演练不计 PRD 开发进度。认证底座的旧接受及公开依据由 PRD 成果入口引用；迁移不重验历史业务或补造原日志。公开依据可能只是检查或审查摘要，完整私人原件没有因此公开。更早的初始化等记录仍在 Git `b921a835` 的 `docs/acceptance.md`，可用 `git show b921a835:docs/acceptance.md` 读取。历史未接受或没有公开成果不能推断未实现；整理不改变任何历史接受状态。
