## 增长与归属

新增独立需求可放 `docs/prds/<稳定名称>/prd.md`，专属设计按实际职责同目录保存；现有 PRD 保持原路径。PRD 只维护需求、范围、安排、验收和未决；设计只维护方案理由，现行模块/接口契约长期维护并由后续需求引用。需要独立维护的工程细节由底座总览链接到 `docs/engineering/`，不按行数机械拆分。新增文档必须可从本导航或相关权威入口发现，不创建空目录和未采用的模板。

需求的必需结果有证据和接受结论后结束该需求；不因结束把 PRD、设计或仍被使用的现行契约搬进 complete。PRD 路径参与任务和成果身份，迁移须显式核对身份、引用和历史恢复。`tasks/complete` 只保存已接受成果的导航、详情与必要依据，历史快照只说明其受验版本；`.work` 保存个人尝试、进度、待接受草稿和原件。维护任务验证后按需 archive，不为收尾生成公共 complete。

同一事实只在上述权威位置维护，其他页面保留必要边界和短链接，不复制完整状态/运行流水。当前实现事实核对源码和现行契约，接受事实核对指定成果详情，两者不互相推导。日常不展开[历史依据](tasks/history/index.md)全文，需要追溯某项旧决定时才按精确链接读取。
