# 协调工具的实现边界

操作判断与生命周期只在[协调协议](../coordination.md)维护，字段与命令只在[记录索引](../work-records.md)维护。本页用于修改工具时核对实现保证，不追加每轮实施经过。

## 职责与记录

任务协调位于 `scripts/harness/work/`，与工程护栏同属 `scripts/harness/`；Profile、启动与产物 smoke 位于 `scripts/service/`。两者按职责检查依赖，运行时不得导入。公共检查验证工具与公开资料，不读取成员的私人记录；本地 `work check` 核对本人的任务。无需个人 Skills、后台服务或第二套进度台账。

ensure 按已注册文档身份与稳定任务键生成／复用记录，update 用 revision 更新允许字段。候选绑定相关内容和契约，成员与物理工作区用于归属；记录阶段、当前校验、人类接受分别判定。旧记录读取不自动升级、重绑证据或改判接受。命令型实施由 `work exec` 核对 C1 后启动，失败修改不自动回滚；它不拦截任意宿主写入，也不是进程沙箱。

源码盘点区分生产、测试、开发脚本、配置、公共资料与生成/运行目录，未知文件拒绝。QUALITY-01 按真实源码 scope 保守触发现有三维审查，包含计划新增路径与删除最后一个源码；只读 inputs 不触发。NORMS-01 用同一个 v2 norms-review 对账需求／方案、现行规范与相关接受；CLI 校验格式、绑定与结论一致性，不能证明人工观察真实。维护不因需要审查而创建开发 result。

## 分层读取与完整性

status 从当前记录生成轻量分页目录，不执行全任务 assess，也不缓存另一份状态。context/check 对选中的任务核对完整输入、证据与恢复条件，默认返回有界投影；记录内超长字段、集合和核验错误用明确引用继续展开。记录中的 RELEASED 不等于当前现场已核验；必要授权或阻塞尚未展示时，模型输出不能据此表示可继续。

guide 默认返回当前动作的章节入口，显式选择后按 Markdown AST 的真实标题边界读取；代码围栏中的示例标题不算导航。read 展开选中的记录、核验或已登记证据；read-result 按 PRD/key 读取公共成果、版本或证据，无需作者记录。分页受输出预算和内容摘要约束，续页遇到内容变化明确拒绝。完整性检查在进程内读取相关字节，与送入模型的正文分开；显式子命令和宿主直接读文件不受这套展示边界强制限制。

`harness.config.json.taskDocuments` 是需求资料的唯一身份注册，类别为 prd/design/proposal。共享 resolver 用于 ensure/update、capture、交付与文档检查；当前目标、必要 alias 与配置进入候选。活动资料由任务总索引经 requirements 导航可达，不能借历史正文取得发现资格。重复身份、未知页、私有/越界/符号链接和孤儿公开产物明确拒绝。

## 每份 PRD 的公共包

明确开发能力才设置 `plan.result={prd,key}`。维护、检查与演练验证后在本人记录中 archive。需求与设计遵循[文档增长规则](../index.md#增长与归属)，不按执行任务或验收项复制长期 Markdown。

新 PRD 使用公共 v4 包：`docs/tasks/complete/<prd-id>/records.json` 保存各成果及内嵌公开证据，`report.md` 是由这些记录生成的按 key 阅读视图。每项仍分别保留候选、HEAD、文件/契约摘要、criterion/method、原件/公开哈希、表示方式、环境与真实接受来源；一个验收项不再要求一个公开 Markdown 文件。报告正文、记录包和总索引均校验完整性，不能只修改其中一份声明另一份仍有效。

读取兼容历史 v1、内嵌 v2 和按 key 拆分的 v3。已有旧 book 的后续交付保持兼容格式，不在新增某个 key 时顺带迁移兄弟快照；显式存量整理遵循[资料增长与归属](../index.md#增长与归属)。私有任务与 prepare/complete 请求继续沿既有契约，公共存储版本不新增生命周期。

v4 的公开证据按逻辑 selector 定位到记录包内相应条目。普通文件摘要继续使用原规则；`records.json#result=<key>` 绑定完整成果及其公开证据，验收项 selector 可定位具体证据。严格解出真实公共路径后再做路径与符号链接检查。涉及共包的 scope 按实际兄弟记录展开，仅排除本人输出，避免自引用与漏掉兄弟依赖；精确输入不会因无关 key 新增而改变。inputStamp 仍检查实际物理文件/目录的身份和变更时间，因此运行期间同一包的并发写入会保守地使验证无效。

## 写入、恢复与保留

prepare 只保存私有草稿和必要附件，必需原件通过并不等于人类接受。complete 接收针对当前候选的真实接受，按 key 更新公共包及索引。新增 key 保留兄弟接受；替换已有 key 要求旧结果与必要证据可从 HEAD 恢复，不能用未提交的唯一快照冒充历史保存。自身输出排除不豁免公开完整性检查。

delivery journal 保存原请求与各目标 before/after 字节；逐文件原子替换配合中断重放与冲突拒绝，不宣称跨文件事务。旧 journal 按原契约核对，已完成旧请求不得覆盖后续合法更新。单 checkout 单写入者，接收者需另核对代码、当前授权和必需原件，不继承发送者的通过。

公开 guard/receive 不依赖作者 `.work`。公开依据可以是原件、脱敏件或摘录，必须保留表示方式；聚合文件不能恢复未保存的原日志。删除 `.work` 会丢失未公开原件、在途任务和恢复记录，archive 仅保留记录并标记历史，不是清理。可重建 fixture 放系统临时目录，不把整仓副本作为长期证据。
