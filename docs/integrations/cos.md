# 腾讯云 COS 使用契约

## 适用范围与接入事实

用户资产和计算结果使用项目独立私有桶，服务端通过固定的 `cos-nodejs-sdk-v5 3.0.0` 接入；A 的源码入口为 [COS 适配器](../../src/integrations/cos.ts)，消费者为[用户资产](../apis/assets.md)与[计算任务](../apis/compute.md)。此能力不启用公开桶，也不复用旧项目的桶或 Root 凭据。实际桶、最小权限、CORS 和真云行为须在目标环境单独验证。

## 必须遵守的约束

- A 的服务端配置为 `MIO_ASSETS_DATABASE_URL`、`MIO_COS_BUCKET`、`MIO_COS_REGION`、`MIO_COS_SECRET_ID` 和 `MIO_COS_SECRET_KEY`，全部未配置时不注册资产入口；部分配置或缺认证时启动失败。秘密只能从受控环境注入，不存入源码、URL 日志或报告；B 使用独立最小权限身份。
- PUT 使用 5 分钟签名和服务端生成的 `mio/staging/<assetId>`；签名绑定声明长度与 Host，HEAD 仍再次核验实际大小与 ETag。浏览器需对应精准 Origin 的 COS CORS；禁止通配公开权限。签名和请求映射以官方 SDK 和真实 COS 验证为准。
- 按冻结的 ETag 条件复制至唯一 `mio/raw/<assetId>/<attemptId>`，发出禁止覆盖头并以抢占身份条件登记。过期抢占可重试，旧执行者不能更改获胜登记；ETag 是 COS 条件标识，不是防碰撞内容证明。复制成功而登记失败可能遗留孤儿，须保留身份供对账，不得把其当已登记资产。
- 上传在 24 小时后过期；服务启动及之后每分钟扫描最多 100 条属于本服务、已过期且不在有效抢占内的 staging，按生成键逐项删除。离线、积压、失败和活跃抢占会延迟清理，失败稍后重试；不扫描桶、不删除未知对象、已登记 raw 或成品。孤儿 raw 不自动删除。
- 下载只对本人已登记资产签发 5 分钟 URL，并要求 attachment 响应；不持久化 URL，文件字节不经 A。桶权限、接口和网络规则不能将临时 URL 或对象键当作用户身份。
- 任务受理前 A HEAD 本人原件并冻结实际 raw ETag；收到成功结果后只 HEAD 当前 attempt 的 derived 键，核对长度、ETag 和 SHA-256 元数据，才在 PG 中同时登记 owner 结果资产及终态。B 用独立身份条件读取 raw、禁止覆盖地写 derived，并按[计算协议](../tasks/compute-service/protocol.md)恢复未知上传；A/B 都不能删除原件或成品。HEAD 核对元数据不等同重新计算对象内容。
- 资产服务关闭时停止受理新操作和启动新的清理删除，等待在途操作；正常对象调用在本地等待最多 180 秒，关闭时最多再等待 5 秒后停止等待 COS 调用，再收敛操作并关闭 PG 池。SDK 的普通请求不提供取消句柄：本地超时不证明云端请求已取消或进程已退出，晚到复制只能形成未登记对象，晚到清理仅作用于到期 staging；重启后按冻结标识和租约恢复。

## 验证入口与变更影响

`tests/assets.test.ts` 使用隔离真实 PostgreSQL、实际插件 HTTP 和受控对象存储替身；`tests/assets-cos.test.ts` 核对 SDK 签名及调用参数。本机隔离测试桶已做小对象 SDK 签名、条件复制、下载和 A/B 分离身份权限正反例；还经真实插件登录入口和 Chrome 以指定 Origin 直传、登记并下载，并确认另一 Origin 的预检被拒。真实 A/B 本机链路与断线恢复也有开发探针。以上均只适用于所测小样本、测试桶和实际候选，不证明生产权限、生产负载或人类接受；已登记测试原件与成品按清单保留。
