## 内容与职责

每份契约按以下四类内容组织，只有实际适用的内容才展开：

- **适用范围与接入事实**：已采用版本及其依据、实际入口、当前消费者与能力边界；区分项目已采用内容和上游可提供的能力。
- **必须遵守的约束**：配置、资源归属、生命周期、错误与副作用，以及适用的依赖边界；给出实现、检查或人工审阅入口。
- **使用经验与适用条件**：注明适用版本、场景、依据和限制，优先链接现有实现与测试；推荐做法不自动成为所有业务的硬性要求。
- **验证入口与变更影响**：实际验证方法、哪些变化影响已有消费者，以及尚未覆盖的范围。

集成专属的公共使用约束在本目录唯一维护，共同工程规则引用原权威页，业务规范直接引用适用契约。业务数据模型、授权、限流规则、缓存失效、产物规格和业务结果由相应业务规范维护；文档集中不改变运行时模块归属，也不要求不同依赖共用一个接口。模型能力契约与具体供应商契约按实际协议划分，共同行为引用、供应商差异保留，不因接口外形相似就认定行为一致。

## 读取与维护

任务沿实际调用关系选择适用契约，包括通过适配器间接使用的依赖；读取和声明方法见[任务建档](../coordination.md#关联并建立当前记录)，变更关系与验证沿[三方对账](../coordination.md#交回与下一步)。导航不等于已经读取，目录和工具不能自动发现全部业务依赖。

采用新依赖时，在首个实现切片的验证前形成必要契约及消费者引用。尚未采用的方案继续保留在所属 PRD 或设计提案中，不写成现行约束。任务结束不搬迁契约页；后续变更更新同一权威正文，已失效经验及时修订或删除，历史由 Git 和接受记录追溯。

本目录属于公共规范，使用现有文档检查、源码边界检查和 `norms-review`。不登记为各 PRD `documents.json` 中的任务资料，不另建状态、进度或契约注册表；检查通过不能代替适用性、遗漏依赖与消费者行为的审阅。
