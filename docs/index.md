## 增长与归属

`docs/` 是公共文档总目录，任务区统一在 `docs/tasks/`。一份新 PRD 通常保留 `docs/tasks/<稳定名称>/prd.md` 与完成后的成果 `report.md` 两份长期阅读文档；复杂设计增加同目录的 `design.md`。提案和取舍优先放入相关设计章节，仅在独立读者与职责确有需要时另设文档，不按执行阶段、子任务或验收项生成一套 Markdown。此数量是组织目标，不得为凑数删掉必要契约与证据。

从[任务总入口](tasks/index.md)经需求导航展开。PRD 维护需求、范围、安排、验收和未决；设计维护方案理由，当前工程、模块、接口与操作行为只引用对应现行规范。新资料须可从入口发现，不从历史或已接受成果正文倒灌活动资料可达性。

来源身份与位置的唯一注册在 `harness.config.json` 的 `taskDocuments`，类别为 prd/design/proposal；identity 首次确定后保持不变，path 为当前位置，aliases 保留兼容入口。`pnpm work documents` 只读核对分类和问题，不自动迁移、重写引用或转移通过。旧页只保留短导航与历史锚点，未知、重复、越界、私有或符号链接资料拒绝。`docs/tasks/index.md` 固定导航到 `requirements.md` 与已接受成果，二者不构成第二份注册台账；complete/history 与活动任务正文分别校验。

需求的必需结果有证据和接受结论后结束该需求；不因结束把 PRD、设计或仍在使用的规范搬进 complete。全部成果统一保存到 `docs/tasks/complete/<prd-id>/`，目录由稳定身份派生。新 PRD 的公共包使用一个按成果键分节的 `report.md` 和一个 `records.json`，记录包逐项保存接受、受验版本和公开证据，报告由该记录生成；不随成果数或验收项数增加 Markdown。读取、依赖与恢复规则见[交付协议](coordination.md#任务交付与重开)。

已有包继续按兼容格式读写，不自动迁移旧接受元数据、成果或历史原件。历史快照只说明其受验版本；`.work` 保存个人过程、待接受草稿与原件，公开摘录不等于完整私人原件。维护任务核对后按需 archive，不生成公共 complete；原件保留与清理不因文件减少而自动完成。

同一事实只在上述权威位置维护，其他页面保留必要边界和短链接，不复制完整状态/运行流水。当前实现事实核对源码和现行契约，接受事实核对指定成果详情，两者不互相推导。日常不展开[历史依据](tasks/history/index.md)全文，需要追溯某项旧决定时才按精确链接读取。
